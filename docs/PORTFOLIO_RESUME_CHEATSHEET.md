### [프로젝트 1] 바이낸스·OKX 선물거래소 차익거래 & 주문 실행 엔진
* **GitHub Repository:** [`funding-arb-engine`](https://github.com/rhwhdgks/funding-arb-engine)
* **직무 적합성:** **거래시스템 백엔드 (95%)** / **퀀트 트레이딩 시스템 (92%)** / **금융 IT 인프라 (88%)**
* **사용 기술:** Python, Asyncio, WebSocket, REST API, MariaDB, SQLite, Linux, GitHub Actions CI

#### 1. STAR 요약 (자소서 복사용)
* **Situation (상황):**
  * 암호화폐 선물 시장에서 두 거래소(Binance, OKX) 간 펀딩비 차익 및 페어 트레이딩 기회를 실시간으로 포착하고, 슬리피지와 체결 시차를 최소화하여 양방향 포지션을 안전하게 운용할 수 있는 무중단 실행 엔진이 필요했습니다.
* **Task (과제):**
  * 양 거래소의 상이한 REST/WebSocket 규격을 단일 인터페이스로 추상화하고, 급격한 시세 변동 시 한쪽 레그만 체결되고 반대쪽 레그가 미체결되는 **실행 불균형(Leg Risk)** 상황을 원천 차단하며, 네트워크 단절 후에도 안전하게 포지션을 복구할 수 있는 **무중단 State Recovery 아키텍처**를 구축하는 것이 핵심 과제였습니다.
* **Action (구체적 해결 노력):**
  1. **양방향 동시 주문 및 Fail-Safe 헤징:** 첫 번째 거래소의 주문 체결 확인 즉시 반대 거래소에 시장가/IOC 주문을 집행하고, 지정 시간 내 미체결 발생 시 즉시 잔여 주문 취소 및 비상 청산(Emergency Unwind) 루틴을 가동하도록 설계.
  2. **장애 복구(State Recovery) 시스템:** 프로세스 재시작 시 거래소 API로부터 실제 열린 포지션과 주문 내역을 전수 조회하여 로컬 MariaDB 및 메모리 상태와 대조·동기화하는 복구 파이프라인 구현.
  3. **이중화 데이터 수집 & 운영 콘솔:** 시세·펀딩비 수집기를 별도 비동기 서비스로 격리하고, 전략 실행 프로세스 내에서 실시간 긴급 일시정지, 위험 축소, 수동 주문 취소를 제어할 수 있는 소켓 기반 운영 콘솔 구축.
  4. **철저한 CI/CD 검증:** 41개의 단위 및 회귀 테스트 케이스를 구축하고 GitHub Actions CI로 자동화.
* **Result (정량적 성과):**
  * **24시간 연속 가동 테스트에서 `final_verdict=PASS` 달성** (잔여 미체결 주문 0건, 불일치 포지션 0건, API 호출 제한 초과 0건 유지).
  * 극한의 변동성 상황에서도 단방향 노출(Unhedged Delta)을 수 초 내에 제로로 수렴시키는 프로덕션급 안정성 검증 완료.

#### 2. 기술 면접 대비 Q&A 포인트
* **Q. 한쪽 거래소만 체결되고 다른 거래소가 타임아웃 나면 어떻게 처리했나요?**
  * **A:** "우선 타임아웃 발생 즉시 해당 주문의 실제 체결 여부를 거래소 REST API로 단건 재조회합니다. 만약 미체결 상태라면 즉시 취소 요청을 보내고, 이미 체결된 반대편 포지션을 즉각 헤지하기 위해 반대편 거래소에 시장가 청산 주문을 집행하여 익스포저를 즉시 제거합니다. 이 모든 상태 전이는 JSONL 감사 로그와 DB에 실시간 기록됩니다."

### [프로젝트 2] 2026 미래에셋증권 AI Festival - DART 전자공시 질의응답 Agent
* **GitHub Repository:** [`mirae-asset-dart`](https://github.com/rhwhdgks/mirae-asset-dart)
* **직무 적합성:** **금융 AI/LLM 엔지니어 (94%)** / **금융데이터 분석가 (90%)** / **핀테크 백엔드 (86%)**
* **사용 기술:** Python, FastAPI, HyperCLOVA X, XML Chunker, Decimal, PyTest

#### 1. STAR 요약 (자소서 복사용)
* **Situation (상황):**
  * 금융감독원 DART 공시 문서는 기업마다 표 형식, 보고 기간, 정정 이력, 단위(원, 천원, 백만원)가 천차만별이어서 일반적인 LLM RAG(검색 증강 생성) 적용 시 환각(Hallucination)과 숫자 왜곡이 빈번하게 발생하는 심각한 문제가 있었습니다.
* **Task (과제):**
  * LLM에게 재무 계산을 직접 맡기지 않고, **"LLM은 자연어 질문 구조화 및 최종 문장 생성만 담당하고, 실제 공시 문서 탐색, 단위 바인딩, 정정 이력 추적, 수치 계산은 엄밀한 파이썬 코드가 수행하는 결정적(Deterministic) Agent 파이프라인"**을 구축해야 했습니다.
* **Action (구체적 해결 노력):**
  1. **단위 바인딩 오류 방지 (`dart_xml.py`):** 문서 상단의 '단위: 백만원'이 엉뚱한 본문 표에 오적용되지 않도록 단위의 유효 범위를 바로 다음 표로 국소화하는 파서 개발.
  2. **정정 공시 계보(Lineage) 추적 (`lineage.py`):** 정정 공시가 발생했을 때 단순히 최신 파일로 덮어쓰지 않고, 과거 특정 분기 시점의 유효 정본과 정정 이력을 그래프 형태로 추적하여 모호한 후보의 임의 선택 차단.
  3. **헤더 보존 결정적 청킹 (`chunker.py`):** 수백 행에 달하는 대형 재무제표 표 분할 시 각 청크마다 최상위 머리글(Header)을 복제 반복하고 행 단위 무결성을 유지하며 Content Hash로 원문 위치를 1:1 보존.
  4. **부동소수점 오차 차단 (`financial.py`):** 부동소수점 오차를 막기 위해 모든 금융 계산에 `Decimal` 모듈을 강제하고, 답변 생성 직전 산출 근거를 재검증하여 허위 숫자 출력을 차단.
* **Result (정량적 성과):**
  * 2026 미래에셋증권 AI Festival 공시 Agent 과제 출품.
  * 복잡한 정정공시 및 다중 단위 환경에서도 환각에 의한 수치 왜곡 0건 달성, 공시 원문 단락 및 표 위치를 100% 추적 가능한 설명 가능한(Explainable) 금융 AI 파이프라인 완성.

#### 2. 기술 면접 대비 Q&A 포인트
* **Q. 왜 LangChain이나 LlamaIndex 같은 기성 프레임워크 대신 직접 파이프라인을 짰나요?**
  * **A:** "기성 RAG 프레임워크는 텍스트 유사도 기반 벡터 검색에 의존합니다. 하지만 금융 공시는 '2024년 3분기 연결재무제표의 매출액(백만원)'처럼 시점, 연결 여부, 단위가 정확히 일치해야 합니다. 벡터 유사도로는 유사한 다른 연도나 별도 재무제표가 검색될 위험이 높아, 질문 구조화와 조건 확정, 정본 조회를 파이썬 코드로 엄격히 제어하는 자체 결정적 아키텍처를 설계했습니다."

### [프로젝트 3] ETF 차트 이미지 기반 수익률 순위 예측 연구 (Find-A 학회)
* **GitHub Repository:** [`etf-image-alpha-ode`](https://github.com/rhwhdgks/etf-image-alpha-ode)
* **직무 적합성:** **퀀트 리서치 (94%)** / **시계열 & AI 모델링 (90%)** / **자산운용 (88%)**
* **사용 기술:** Python, PyTorch (2D CNN), pandas, NumPy, SciPy, Walk-Forward, Purge/Embargo

#### 1. STAR 요약 (자소서 복사용)
* **Situation (상황):**
  * 고려대학교 퀀트 학회 Find-A에서 7개 주요 ETF를 대상으로, 가격 차트 이미지가 전통적인 수치 시계열 데이터보다 향후 20거래일 뒤의 ETF 간 상대적 수익률 순위를 예측하는 데 추가적인 알파(Alpha)를 제공할 수 있는지를 과학적으로 검증하고자 했습니다.
* **Task (과제):**
  * 60거래일 OHLCV 데이터를 2D 이미지로 변환해 CNN으로 특징을 추출하고, 미래 참조 편향(Look-Ahead Bias / Data Leakage)을 완벽히 배제한 상태에서 포트폴리오 최적화(Neural ODE) 팀에 전달할 신호 $\mu(t)$와 공분산 행렬 $\Sigma(t)$를 산출하는 엄격한 연구 파이프라인을 구축하는 것이었습니다.
* **Action (구체적 해결 노력):**
  1. **철저한 Data Leakage 방지:** 시간 순서를 보존한 Walk-Forward 교차 검증을 적용하고, 20일 예측 윈도우 겹침 문제를 해결하기 위해 Fold 경계에 **Purge 및 Embargo 기법**을 적용하여 미래 정보 유출을 차단.
  2. **차트 이미지 팩터 어블레이션 (Ablation Study):** 2D CNN을 통해 추출한 이미지 특징이 단순 모멘텀/변동성 팩터 대비 통계적으로 독립적인 추가 예측력을 제공하는지 다중 가설 검정 및 부트스트랩으로 엄밀히 검증.
  3. **공분산 행렬 축소 추정 (Shrinkage Covariance):** 표본 수가 적을 때 공분산 행렬이 왜곡되는 문제를 막기 위해 Ledoit-Wolf Shrinkage 기법을 적용하여 안정적인 $\Sigma(t)$ 행렬 생성.
  4. **학회 팀 간 인터페이스 표준화:** ODE 팀이 즉시 포트폴리오 최적화 연산에 투입할 수 있도록 Manifest 기반 표준 입력 스키마(Handoff Protocol) 정의.
* **Result (정량적 성과):**
  * 연구 전 과정을 담은 한국어 논문 연구 초안(`paper_draft_ko.md`) 및 프로세스 무결성 감사 보고서(`process_integrity_report.md`) 완성.
  * 이미지 단독 모델보다는 거시 시장 공통 요인을 통제한 잔차 모델에서 이미지 패턴이 유의미한 보조 지표로 작동함을 실증.

### [프로젝트 4] 바이낸스·OKX 코인 주문흐름(Order Flow) 동조화 연구
* **GitHub Repository:** [`crypto-order-flow-synchronization`](https://github.com/rhwhdgks/crypto-order-flow-synchronization)
* **직무 적합성:** **마켓 마이크로스트럭처 리서치 (96%)** / **퀀트 데이터 엔지니어 (92%)**
* **사용 기술:** Python, Parquet, NumPy, pandas, SciPy, L2 Order Book, Research Pre-registration

#### 1. STAR 요약 (자소서 복사용)
* **Situation (상황):**
  * 여러 암호화폐 자산의 매수·매도 체결 압력(Order Flow)이 개별 자산의 고유한 뉴스가 없음에도 시장 전체에서 동시에 같은 방향으로 움직이는 동조화 현상이 존재하는지 실증적으로 규명하고자 했습니다.
* **Task (과제):**
  * 수 기가바이트에 달하는 바이낸스와 OKX의 틱(AggTrades) 및 L2 호가 데이터를 처리하고, 가격 변동 및 거래량 영향을 통제한 뒤, 연구자의 자의적 개입(p-hacking)을 배제한 사전 등록 연구 설계(Pre-registered Research Protocol)를 통해 가설을 검증해야 했습니다.
* **Action (구체적 해결 노력):**
  1. **사전 등록 및 Seal 봉인:** 분석 결과를 보기 전 가설, 기간, 자산, 판정 임계값을 담은 프로토콜을 사전 등록하여 사후 편향 방지.
  2. **체결 압력 잔차화 (Orthogonalization):** 단순 동시 움직임이 시장 전체의 급등락이나 거래량 충격 때문이 아님을 증명하기 위해, 회귀 분석을 통해 가격 변화율과 거래량 효과를 걷어낸 순수 잔차 주문흐름(Residual Order Flow) 추출.
  3. **외부 타당성 (External Validation) 검증:** 분석에 사용하지 않은 미래 기간과 완전히 다른 거래소인 OKX 데이터를 동일 파이프라인으로 검증.
  4. **현실적 거래비용 검정:** 동조화 현상을 이용한 차익/시차 추종 매매 전략을 백테스팅하고, 슬리피지와 거래소 수수료를 감안한 실제 순익 유효성을 평가.
* **Result (정량적 성과):**
  * 7개 코인 간 주문흐름 상관계수가 **실제 자료 0.14345 vs 무작위 날짜 셔플 비교값 0.00114**로 통계적으로 유의미한 동조화가 존재함을 규명. OKX에서도 상관계수 0.11857로 교차 검증 성공.
  * 단, 이를 활용한 단순 추종 매매는 거래비용 감안 시 알파가 소멸됨을 확인하여, **"통계적 유의성이 곧바로 실행 가능한 초과수익으로 이어지지 않는다"**는 금융 시장의 본질적 교훈을 데이터로 입증.

### [프로젝트 5] 암호화폐 집단추종(Herding) 지표 검증 및 가상시장 시뮬레이션
* **GitHub Repository:** [`crypto-herding-research`](https://github.com/rhwhdgks/crypto-herding-research)
* **직무 적합성:** **계량 금융 리서치 (95%)** / **데이터 사이언스 (91%)**
* **사용 기술:** Python, CSAD 모형, 몬테카를로 시뮬레이션, 가상시장 에이전트 모델링

#### 1. STAR 요약 (자소서 복사용)
* **Situation (상황):**
  * 금융 저널(JBEF, 2026)의 선행 논문이 제시한 CSAD(횡단면 수익률 분산) 기반 집단추종 지표가 "실제 투자자들의 모방 매매 때문인지, 아니면 수학적 모형 자체의 기계적 왜곡인지"에 대한 의문이 들었습니다.
* **Task (과제):**
  * 선행 논문의 62개 코인 분석 결과를 완벽히 재현한 후, **"투자자 간 상호작용(모방 거래)이 전혀 존재하지 않는 순수 무작위 가상시장"**을 구축하여 해당 지표가 가짜 신호를 만들어내는지 반증 실험을 설계하는 것이 과제였습니다.
* **Action (구체적 해결 노력):**
  1. **선행 논문 재현:** CoinMarketCap 62종목 1분봉 데이터를 수집하여 논문에 기록된 음(-)의 회귀 계수를 오차 범위 1% 이내로 재현 성공.
  2. **영가설 가상시장 에이전트 시뮬레이션:** 투자자가 서로를 따라 하지 않고 개별 정보에만 반응하는 가상시장 몬테카를로 시뮬레이션 환경 구축.
  3. **기계적 유도 수식 규명:** 극단적 시장 충격 시 자산 간 변동성 불일치로 인해 집단추종이 없어도 CSAD 계수가 음수로 떨어질 수밖에 없는 수학적 원인 도출.
* **Result (정량적 성과):**
  * 집단추종이 전혀 없는 가상시장에서도 선행 논문과 동일한 집단추종 판정 계수가 **97~100%의 빈도로 거짓 양성(False Positive)**으로 검출됨을 증명.
  * "기존 학계 지표의 맹점을 과학적 시뮬레이션으로 반증"해 낸 계량적 비판 사고와 모델 검증 역량을 증명.

Spring Boot의 계층형 아키텍처(Controller-Service-Repository)와 JPA 영속성 컨텍스트는 제가 구현한 라우터-엔진-DAO 계층 구조와 개념적으로 1:1 대응합니다. 고려대 컴퓨터공학 전공을 통해 다진 객체지향 CS 기초와 Linux 환경 경험을 바탕으로 스프링 생태계에 빠르게 적응할 것을 약속드립니다."

3. **Q. RAG에서 왜 벡터 DB보다 정형 규칙과 코드 처리를 강조했나요?**
   * **방어 논리:** "일반 챗봇은 유사한 의미의 문장만 찾아도 되지만, 금융 공시는 '단위(원 vs 백만원)'나 '연결 vs 개별' 재무제표가 하나만 어긋나도 숫자가 1,000,000배 틀려집니다. 임베딩 벡터는 '2024년 3분기'와 '2023년 3분기'를 매우 유사한 벡터로 인식하기 때문에 검색 실패가 잦습니다. 그래서 검색 조건 확정, 단위 결합, 정정공시 타임라인 추적은 100% 결정적인 Python 코드로 제어하고, LLM은 자연어 문장화에만 한정하는 하이브리드 설계를 채택했습니다."
